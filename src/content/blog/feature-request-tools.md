### What is a feature request tool?

A feature request (or feature request form) is a tool that is used to capture and track user feedback and suggestions for a product, website, or application. It allows users to submit ideas and suggestions by filling out a short form. This helps developers get feedback from the people who are using the product, and it also allows users to provide feedback in a more organized way.

Feature request forms are an important part of any software development process. By using a feature request form, developers can more easily identify and solve problems that are being faced by users. Additionally, it can help developers prioritize the features that they want to develop.

Having a feature request form in place can also help developers track the progress of their projects. This will help them to determine when certain features are finishable, and it will also help them to assess how well the features are being used.

Overall, having a feature request form in your development process will improve the overall quality of your software products.

### How to track Feature Request?

Tracking Feature Requests (FRs) is an important part of any software development project. It helps you to understand the needs of your users and to prioritize the features that need to be developed. There are a number of different ways to track FRs, and the approach that you choose will depend on the type of project that you are working on.

One popular way to track FRs is using a software development framework like JIRA. This platform enables you to create and manage projects, assign tasks to team members, and track milestones and tasks. You can also use JIRA to create custom fields for tracking FRs.

Another popular way to track FRs is using a customer feedback tool like SurveyMonkey. This platform enables you to survey your customers and collect feedback on a variety of topics. You can also use SurveyMonkey to create surveys that ask about specific FRs.

If you are working on a project that does not require any customization or special features, then tracking FRs using a simple spreadsheet may be the best option for you. Simply enter the name of the FR, the date that it was created, and any other relevant information. This approach will allow you to quickly identify which features are being requested most frequently and determine which ones need more attention from your team.

Whatever method you choose, make sure that it is effective in tracking FRs and helping you to prioritize the features that need to be developed.

### How To Collect Feature Requests

There's no one-size-fits-all answer to this question, as the best way to collect feature requests depends on the specific needs of your business. However, some tips that may be helpful include:

1\. Create a user interface that's easy to navigate - Make sure your users are able to find what they're looking for quickly and easily. This means creating simple and easy-to-understand menus, buttons, and labels.

2\. Make it easy for users to report problems - Make sure you have a system in place for users to report any issues or bugs they may encounter. This way, you can quickly address these issues and keep your users happy and satisfied.

3\. Increase the visibility of your feature requests - Make sure your feature requests are easily accessible both on your website and on social media platforms like Twitter and Facebook. This will help you attract more attention from potential customers and partners, as well as increase the chances of receiving feedback that will help you improve your business.

4\. Keep track of progress - Make sure you track the progress of each feature request so you can see how well it's being implemented and whether any changes are necessary. This way, you can make informed decisions about which requests to prioritise and how best to allocate your resources.

- Add a new issue - This allows developers to raise a new issue for their project. This issue can have any kind of content, such as a bug, suggestion, or question.

- View comments on a pull request - When someone reviews a pull request, they are able to leave comments on it. Comments can be helpful in clarifying why someone wanted to make the change they did and how it impacts the codebase as a whole.
